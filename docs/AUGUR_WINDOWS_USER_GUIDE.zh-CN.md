# Augur · Windows 使用说明

## 1. 首次启动

1. 将 Windows ZIP **完整解压**到本机可写目录，例如 `D:\Augur`。不要在 ZIP 里直接运行。
2. 首次可执行 `Verify-Package.cmd` 校验包文件及运行环境。它不是 GPU 性能测试。
3. 双击 **`启动服务.exe`**。第一次打开会先请你选择界面语言（简体中文或 English，默认简体中文）；之后作为偏好保存在 `%LOCALAPPDATA%\Augur\preferences.json`，配置页、聊天页和监控页都跟随它，随时可以在页面右上角切换。后台启动器自动打开浏览器中的本地配置页，不弹出命令行窗口。之后再双击，会直接用已保存的配置加载模型；服务已在运行时只会重新打开配置页。需要看控制台诊断时可改用 `Start-Augur.cmd`。
4. 选择 QUASAR 原始 NVFP4 主模型目录。当前仅支持 `qwen3.8-27b-quasar-nvfp4`，API 模型名为 `quasar-27b`。
5. 选择原始 DFlash BF16 目录，点击“一键量化并选用”；也可以直接选择已有的兼容量化目录。
6. 选择上下文、API 端口和 Vision 策略，点击“保存并重启服务”。加载完成后点击“打开模型聊天”。选择 KV 容量时，“默认单次输出上限”自动填为该容量的 95%，可以手动改小。
7. 用完点配置页里的“退出 Augur”：先关闭服务、确认显存释放，再结束后台启动器。

需要 Windows x64、支持该 SM70 构建的 NVIDIA GPU 及驱动。包内包含运行时，不要求用户安装 Python、Conda、CUDA SDK 或 PyTorch。模型权重不随引擎发布。配置页地址和模型 API 地址是**两个不同端口**；API 默认 `http://127.0.0.1:8294/v1`。

配置文件默认保存在 `%LOCALAPPDATA%\Augur\config.json`，运行日志在同目录的 `runs`。默认设置页端口自动选择。配置页链接里的 `#key=` 是本地管理授权，请勿分享；启动失败时会弹窗提示，详细信息在同目录的 `launcher-start.log`。浏览器只连接本机，不上传模型文件。

## 2. DFlash 一键量化

原始目录需要 `config.json` 和 `model.safetensors`，当前仅接受已支持的原始五层 DFlash2 权重身份。Rust 量化器直接读取 safetensors：48 个矩阵量化为 Q8_0，norm/卷积状态基保留 FP32，selector gate 从原始浮点权重转为 FP32 并折入一次 0.45；运行时 scale=1，不重复缩放。

默认输出为解压目录下的 `user-data\models\dflash-q8-fp32-gate045`，可以改到其他本机磁盘。输出 GGUF 为 **2,060,264,832 bytes，约 1.919 GiB**，另有小型配置和回执；量化器要求输出空间外加 128 MiB 发布余量，实用建议至少留 **3 GiB** 空闲。不包含原始 BF16 权重或 target 所占空间。

按钮依次执行原始权重检查、空间计划、量化、输出完整性/身份检查和配置保存。完整匹配的已有结果可复用；不覆盖现有目录，不修改或删除原始权重。运行中的引擎不会因量化自动切换，量化完成后点击“保存并重启服务”。中断可能留下 `.augur-q8-partial-*`，不能当成完成模型；确认量化进程结束后再人工处理。格式转换成功不等于任意模型的语义验收通过。

## 3. KV 上下文选择

| 界面档位 | 实际 token 容量 | 最大允许单次输出（容量 95% 向下取整） |
|---|---:|---:|
| 8K | 8,192 | 7,782 |
| 32K | 32,768 | 31,129 |
| 64K | 65,536 | 62,259 |
| 128K | 131,072 | 124,518 |
| 192K | 196,608 | 186,777 |
| 256K | 262,144 | 249,036 |

选择会传入原生 owner，改变**真实 KV 分配容量**、native health 回执和请求预算，而不只是前端显示。输入、工具定义、图像 token、历史、思考和答案**共用**这份容量。系统仍须为已有输入留出空间，因此可生成量不等于表中的输出上限。模型自身位置设置未扩展；当前采用完整上下文而不是滑动窗口。

“默认单次输出上限”只用于未指定额度的请求。DSH 等客户端显式传入 `max_completion_tokens` 时，请求值优先，但不能超过所选档位的输出上限。超出限制明确报错，不会悄悄截断历史。客户端压缩/摘要需要客户端实现，设置 95% **并不表示引擎会自动压缩对话**。

当前界面不提供温度、top-p、top-k 或惩罚项；默认使用 target 采样（temperature=1、top-p=0.95、top-k=20、min-p=0、presence/frequency penalty=0、seed=0）＋固定 B8 概率草稿；selector 内嵌 FP32 gate0.45，验收使用实际 q 的 p/q 接受与残差修正。Vision 默认按需加载，可显式选择优先常驻、长 prefill 显存压力时回收。

## 4. 保存重启与关闭服务

- **检查配置**：验证路径、模型身份和可用配置，不保存、不停服务。
- **保存并重启服务**：先检查候选配置，再中断当前请求、关闭旧引擎，确认清理后保存并启动新引擎。不允许新旧 GPU owner 重叠。
- **关闭服务**：中断当前生成，排空请求，等待原生退出及显存分配清理确认；配置页继续保留，之后可重新启动。
- 浏览器标签关闭不等于停止服务。请先点击关闭服务，再关闭启动器窗口。控制台 Ctrl+C 会尝试协作清理；强制结束进程或关机不能保证完整写盘。
- 清理未确认时不会自动启动另一个 owner；检查日志和 GPU 进程后处理，不能把错误状态视为显存已释放。

GPU 清理确认指本进程的原生 allocation ledger 清零，不代表系统驱动占用为零。重启后活跃会话不保留；浏览器旧对话若继续发送，必须重新校验，持久化缓存只可能减少相同输入前缀的重新计算。

### 实时监控入口

服务启动后，配置页状态区提供 **“打开实时监控”** 按钮，与“打开模型聊天”并列。启动器自动为本次服务创建只读监控面板，端口自动分配，无需手填，也不会指向旧的测试监控。

面板显示 GPU 利用率、显存占用/可用量、生成中的近 5 秒实时 TPS、prefill TPS，以及最近完成请求的 DFlash 接受率/已检查草稿命中率。没有活动生成时实时 TPS 显示待机；prefill 完全来自状态复用时不虚报 TPS。接受率采用 accepted/proposed，已检查命中率采用 accepted/checked，两者分母不同。

点击“关闭服务”后监控保留，可以查看引擎离线和显存释放；关闭启动器时监控一并退出。更改端口并重启后，使用配置页提供的新监控链接，避免继续查看旧标签。监控端口只监听本机，不提供模型提示词、输出正文或 API 密钥。

## 5. 256K 前缀缓存持久化

勾选“保存可恢复的输入前缀”，选择私有、本机、可写的缓存目录。启动器开启**纯输入尾部快照**；完整输入命中可复用保存的 logits，分叉请求只复用已有的最长可恢复边界。

缓存不仅是 KV：还包括对应边界的 GDN 递推状态、卷积历史、DFlash target feature ring、logits 和 token/身份元数据。终点 GDN 不能直接裁剪成更早的状态。缓存中没有模型权重，也不是完整聊天记录的备份。

目录按 `context-实际容量\构建与模型身份哈希\...` 分开。同一配置与兼容构建重新启动后扫描已有索引；构建二进制、target、draft 或数值绑定变更会使用新命名空间，旧缓存不自动删除。图像状态不纳入这条纯文本前缀缓存。

### 多窗口与多条长前缀是什么关系？

**窗口数不等于缓存条目数。** 浏览器窗口/标签页是交互入口；一条持久化缓存则是某个精确 token 前缀及其对应的 KV、GDN 等状态快照。磁盘按实际保存的快照数量和长度占用，不按打开了几个窗口计费。

以下情况以多个窗口连接**同一个本机引擎、同一个兼容缓存命名空间**为前提：

| 使用方式 | 与缓存条目的关系 |
|---|---|
| 两个窗口发送完全相同的长输入 | 已有对应缓存且身份兼容时，可以复用同一条，不必因为多开窗口再保存一份。 |
| 两个窗口分别使用不同的长文档 | 通常需要分别保存不同条目；是否还能复用较短共同前缀，要看是否存在对应的完整可恢复快照。 |
| 同一个窗口，先保存 32K 输入，后又保存 64K 输入 | 可能留下两条不同长度的快照；同一窗口不等于只能占一个条目，也不意味着每轮都会必然新增条目。 |
| 两个窗口使用相同文档，但末尾问题不同 | 只有在共同文档结束等分叉边界已有可恢复快照时，才能复用到那个边界。只有“文档＋问题 A”的尾部快照，不能直接裁掉问题 A，当作“文档＋问题 B”的共同状态。 |
| 关闭一个或全部浏览器窗口 | 不会自动删除磁盘上的持久化缓存，也不会自动停止模型服务。 |

判断“相同输入”看的是**实际 token 序列**，不只是界面上看起来相同的文档：系统提示词、工具定义、聊天模板、历史内容或其排列不同，都可能改变前缀。当前保存的是纯输入尾部快照，不会自动为所有可能的分叉点生成快照，也没有承诺把不同条目中的共同 KV 块在磁盘上去重。

**缓存复用与并发生成是两回事。** 多个窗口应连接同一个服务，而不是每开一个窗口就再启动一套引擎。当前单 GPU 服务按串行请求规则工作，多窗口不代表同时运行多路生成；服务忙时，客户端需按接口响应等待或重试。选择 256K 也不意味着给每个浏览器窗口单独常驻一份 256K GPU KV。

因此，后文的磁盘建议应这样理解：

- **10 GiB**：按一条接近满 256K 的缓存准备，不是“每个窗口 10 GiB”。
- **24 GiB**：适合约两条接近满 256K 的缓存并留余量；同一窗口不断产生新快照，也会逐渐用完这些空间，不能无限累计。
- **80 GiB 以上**：为保留多个长文档前缀或同一对话的多个历史版本准备，不是打开多个窗口的硬性要求。

建议先让多个窗口使用相同的系统提示、工具定义和文档组织方式，再观察真实缓存命中与磁盘增长。需要释放磁盘空间时，先关闭模型服务，再按下文规则处理不再需要的缓存；不要把关闭标签页当成清理缓存。

### 单条缓存大小：按实际序列长度计费

设已消耗输入长度为 `n`，KV 行按 256 对齐。当前源码中：

- 16 层全注意力、K/V 两份，每行各 1,088 bytes：`ceil(n/256) × 256 × 34,816 bytes`。
- 48 层 GDN 状态：150,994,944 bytes。
- 48 层卷积历史：5,898,240 bytes。
- DFlash target feature ring：最多 209,715,200 bytes（2,048 行×5层×5,120×FP32）。
- logits：993,280 bytes。
- 再加 token 描述及清单；每条磁盘预留还包含 **40 MiB＋4 KiB** 的元数据上界。

接近档位上限的估算如下（未把 descriptor 与清单的实际字节伪装成精确实测）：

| 输入接近 | KV＋GDN＋卷积＋feature ring＋logits |
|---|---:|
| 8K | 0.608 GiB |
| 32K | 1.405 GiB |
| 64K | 2.467 GiB |
| 128K | 4.592 GiB |
| 192K | 6.717 GiB |
| 256K | **8.842 GiB** |

即使选择 256K，短输入快照也不会写满 8.842 GiB。接近满长度时 `n < 262144`，对齐后的 KV 最大仍为 8.5 GiB，加上其他状态后接近 8.842 GiB。可以在运行回执的 `payload_bytes` 查看本次实际负载。

### 至少给硬盘留多少空间？

- **只存一条近满 256K 缓存：至少按 10 GiB 空闲预算。** 这是缓存新增空间，不包含已经存在的模型/程序；运行时仍会按实际 payload 和元数据余量检查磁盘。
- **正常使用建议至少 24 GiB 空闲。** 足够容纳一条旧缓存及一次接近满长度的新保存并留余量；配置页以此作为启用 256K 持久化的保守检查值。它不是数学上的最小需求。
- **希望保留多个长前缀：建议初始预留 80 GiB 以上。** 当前单个命名空间的限制是最多 8 条、合计预留 64 GiB，两者先到者为准；近满 256K 快照通常先达到字节限制，约能保留 7 条，而不是保证有 8 条。
- 配额满后，新的自动捕获会被跳过，已有条目继续可用；当前没有自动 LRU 删除。切换构建/档位产生的多个命名空间**不共享一个全局 64 GiB 限额**，需要用户管理总空间。

写盘分块暂存后提交清单，**不是额外再复制一份完整 payload**；但保存新条目时旧条目仍存在，所以必须按“已保留条目＋新条目”计算峰值。失败/中断的 reservation 保留并占配额，不会被当成有效缓存或静默删除。先关闭服务，保留必要日志，确认命名空间不再使用后再人工清理；不要在运行期间删除缓存文件。

以上仅为缓存盘建议。若缓存、模型与程序同盘，需另外计入 target 权重、原始 BF16、约 1.919 GiB 的量化输出、Windows 解压包、日志及下载 ZIP。原始 BF16 不自动释放，公开包中不包含用户缓存、权重或密钥。

源码依据：`checkpoint_target_cuda/checkpoint_io.rs`、`checkpoint_linear_cuda.rs`、`checkpoint_target_cuda/dflash_capture.rs`、`augur_session_cuda/checkpoint.rs`、`session_checkpoint/http_filesystem.rs`。磁盘大小分析不代表已经完成完整 256K prompt 的 GPU 性能测试；GPU 验收范围以对应构建的运行回执为准。

## 8. 监控中的 Prefill、Decode 与上下文进度

Prefill TPS 使用 **Native 执行组件口径**：实际新计算 token ÷ `execute_with_upload_head_capture_seconds`。执行时间包含输入上传、前向、head 和草稿特征捕获，不包含缓存保存/恢复、工作区准备/释放或 HTTP。对应的 Native 耗时与表格使用同一计时。完整缓存命中显示未执行；缺少与 token 数匹配的原生计时时显示 —，不会回退为整体请求墙钟。整体 `prefill_wall_s` 仍保存在原始账单及监控 API，供 TTFT 分析。

“最近完成请求”右侧的 **清空历史记录** 只清空当前浏览器、当前监控地址下的列表。刷新页面后仍保持清空，新完成请求自动显示；同一浏览器中打开相同监控地址的标签同步更新。原始性能账单、模型对话、缓存文件及实时指标保留，不影响模型生成。更换浏览器或监控端口后不共享这项显示设置；浏览器禁止本地存储时，页面会提示刷新可能恢复。

顶部提供 **Decode TPS**（最近5秒的已验证输出 token / 墙钟）与 **Prefill TPS**（最近完成请求的新计算输入 token / Native 执行时间）。完整缓存命中显示“未执行新 prefill”，不会用缓存 token 虚增 TPS。DFlash 接受率、已检查草稿命中率仍保留在请求明细表。

**KV 上下文占用**显示当前请求使用的 token 与实际选择容量；生成期间随已验证输出增加，切换会话、压缩或重新提交较短历史后可下降，不累计其他窗口或旧请求。预填充期间显示已计入的输入额度，不表示每层 KV 已全部写入；完成时包括待消费尾 token。显存预分配单独显示，它不会因为短提示而按相同比例缩小。停服后 token 数标记为最近请求，KV 活跃显存显示0。

进度条在 **95%** 标出压缩提示线。256K = **262144 token**，对应 **249036 token**；到线后提示客户端在请求边界压缩。引擎不会在一段尚未结束的思考中自动插入摘要。DSH 的 `contextWindow` 同样设262144、`maxTokens` 设249036，安装脚本会同时配置95%策略。DSH 按客户端估算判断压力，引擎监控按实际 token 账单显示，因此不能把提示条当成 DSH 已经执行压缩的确认。


## 服务入口与重启状态

点击“保存并重启服务”后，页面立即显示动态加载标记、累计用时和当前阶段用时。校验模型、关闭旧服务与释放显存、保存配置、加载主模型 / DFlash / KV、连接监控分别显示真实状态。结束后保留总耗时；失败会保留错误信息，不用固定倒计时推测完成时间。加载期间请勿退出启动器。

聊天与监控按钮会读取当前启动器状态再连接。模型服务停止后，聊天暂不可用；重新启动后，从配置页点击“打开模型聊天”可取得当前有效入口。API Key 的规则见下文“API Key 与接入其他 Agent”。监控在重启模型时保持同一地址；退出整个启动器后，下次优先复用保存的监控端口，端口被占用时会重新分配，请以配置页按钮为准。关闭浏览器标签不会关闭引擎；退出启动器会关闭其管理的服务。

解压后双击发布目录中的 `启动服务.exe` 打开配置页。

## API Key 与接入其他 Agent

发布包里**不含**任何 API Key。首次启动时在本机生成一个，保存在 `%LOCALAPPDATA%\Augur\api-key.txt`。服务重启、升级到新版本、换解压目录都继续使用同一个，已配置好的 Agent 不用改。

- **聊天页**：从配置页或“启动服务.exe”打开时自动带上密钥，并记在浏览器里。以后直接打开 `http://127.0.0.1:8294/` 也能进，不需要输入。密钥失效时页面会提示重新从配置页打开；设置里仍可手动粘贴。
- **环境变量（默认开启）**：启动器写入当前用户的环境变量，不需要管理员权限：`AUGUR_API_KEY`、`AUGUR_BASE_URL`（如 `http://127.0.0.1:8294/v1`）、`AUGUR_MODEL`（`quasar-27b`）。只对之后新打开的终端和程序生效，已经开着的要重开。不会修改 `OPENAI_API_KEY`。在配置页取消勾选后，启动器只删除它自己写入的值。
- **其他 Agent**：任何 OpenAI 兼容客户端填 Base URL、模型名和密钥即可。能读环境变量的填 `AUGUR_API_KEY`，不能读的在配置页“接入其他 Agent”里点“复制”再粘贴。
- **自己指定密钥**：启动前设置用户环境变量 `AUGUR_API_KEY`（至少 32 个可见 ASCII 字符，不含空白），启动器会采用它并写回 `api-key.txt`。DSH 等已有配置可以用这种方式与引擎保持一致。
- **更换密钥**：怀疑泄露时在配置页点“更换 API Key”。旧密钥立即失效；服务在运行时会自动重启。环境变量和聊天页随之更新。

密钥只在本机：私有数据目录、当前用户环境变量和本机浏览器存储。不进发布包，不写进日志，配置页的状态接口也不返回它。服务只监听 `127.0.0.1`。环境变量对本用户运行的所有程序可见，这是“免输入”的代价；不需要时关闭即可。

## 长输出中断与思考循环

Native 传输对整次响应使用128 MiB字节上限，逐帧仍限制4 MiB；这是流式字节校验，不预分配128 MiB显存。256K容量和249036-token默认输出上限不变。旧版本的16 MiB累计上限可能在约8万多输出token时中断长回复，新版已修复。

贪婪解码时自动开启长思考完全重复检测（`AUGUR_REASONING_LOOP_GUARD=auto`，默认）。贪婪解码一旦进入精确循环就无法自行跳出；默认的采样解码（temperature 1）会自行离开循环，因此不做检测。`on` 在采样时也强制检测，`off` 完全关闭。检测规则：思考通道中同一128～16384字符片段至少连续重复6次，且累计完全重复至少8192字符时，停止当前这段生成并返回 `reasoning_repetition`，由 Harness 决定如何恢复任务。这不是正常长思考的token上限；最终答案和工具内容不经过此检测。已经流出的思考保留在客户端，未提交为成功完成的回复，不伪造最终答案，直接调用 API 的客户端收到明确错误；配置了 Augur 恢复插件的 DSH 会在同一任务内恢复，详见下文。检测用于停止确定的重复消耗，不能证明或改善模型推理质量，也不能检测所有语义循环。

若DSH日志仍提示“249036 completion tokens + 65536 headroom leaving no pressure budget”，按DSH集成说明重新配置预设并重启DSH；仅更改宿主同名压缩插件不能更新已隔离的Agent预设。


## DSH 循环恢复与切换会话

运行配套配置脚本后，DSH 对 Augur 的重复思考信号最多执行两次同任务恢复。第一次追加恢复提示，临时使用 low 思考、输出最多8192 token；第二次临时关闭思考、输出最多16384 token，要求转入答案或工具行动。不会超过用户设置的更低输出上限。原任务、已完成工具结果保留，失败请求的大段思考不重新塞回模型。恢复后的半截输出不算成功；两次仍失败才结束本轮，保留错误记录。成功以后恢复原思考档位和输出上限，用户主动停止不触发恢复。

本机模型一次服务一条生成。切换会话不会自动终止旧会话；同一个 DSH 进程中的 Augur 请求按先后排队，等待中的任务可随时停止。点击停止后，DSH 任务结束与 Rust 排空存在短暂间隔；插件会对尚未接纳、尚无输出的 `single_user_busy` 自动等待重试，最多30秒。已输出的请求不会因409被重放。其他程序独立发来的并发请求仍遵守引擎单请求限制。

这项恢复经过确定性流程测试，并不保证模型遇到任何循环都能产出正确答案；当前检测针对足够长的完全重复片段。


## 工具列表变化后继续原会话

DSH更新插件、重命名或关闭工具后，旧会话里的调用和结果仍可以作为历史保留。例如历史为 `browser_session`，当前工具名为 `bsk_session`，不应删除原对话来绕过校验。Augur分别处理历史结构和当前生成权限：旧记录检查格式及结果配对；本次新调用必须出现在当前工具列表并通过参数校验。浏览器CLI等外部工具是否安装、执行是否成功，仍由DSH自身管理。
